收藏标准

优先收录以下内容：

  • 有真实实验、代码、数据或事件作为依据；
  • 能帮助理解 AI Native 产品、Agent、安全或基础设施；
  • 不只给结论，还公开研究方法、限制或修复建议；

AI 安全与 Agent Security

001 · Hacking OpenAI

  • 原文：Hacking OpenAI — Hacktron AI
  • 作者：Harsh Jaiswal、Mohan Pedhapati、Rahul Maini
  • 发布日期：2026-09-13
  • 关键词：AI 辅助漏洞研究、libheif、ImageMagick、Discourse、SSO、身份边界、Codex、供应链

一句话摘要

研究团队将 libheif 图像解析漏洞与 OpenAI SSO 身份配置问题串联，证明一个看似独立的社区论坛入口，可以进一步影响 ChatGPT、Codex 及其已经连接的内部资源。

研究讲了什么

攻击链从用户可控的 HEIF/HEIC 图像开始。Discourse 的图像处理流程会调用 ImageMagick，进而把文件交给存在内存安全问题的 libheif 解析。研究人员借助 Claude 模型分析依赖、开发并适配利用方式，获得论坛环境的代码执行能力。

真正扩大影响的并不只是图像解析漏洞，而是身份边界：被攻陷的论坛与 OpenAI 账户体系之间存在 SSO 信任问题，使论坛入口可能进一步转化为 ChatGPT 和 Codex 账户访问。如果相关账户已经连接 GitHub 等服务，风险还会沿连接器继续扩散。

研究团队通过负责任披露与 OpenAI、Discourse 协调修复，并用不读取内部敏感代码的方式证明影响。

为什么值得收藏

  1. 展示了 AI 对漏洞研究经济性的改变：模型没有凭空发现全部问题，但显著压缩了依赖分析、内存破坏利用和跨环境适配所需的时间。
  2. 说明身份边界往往比单个漏洞更重要：一个外围服务的 RCE，因为 SSO 与连接器信任，可能升级为核心账户和内部资源访问。
  3. 揭示了“已知修复但未回补”的供应链风险：上游代码已经发生安全相关变化，不代表发行版依赖、容器镜像和生产系统已经获得修复。
  4. 适合作为 AI 业务安全案例：风险不只来自模型本身，还来自模型能够接触的账户、连接器、代码仓库和第三方服务。

我准备继续关注

  • AI 模型在内存安全研究中的实际能力边界；
  • SSO 中身份绑定、会话继承和跨产品信任的设计；
  • Codex、Agent 与外部连接器之间的最小权限和二次确认；
  • 图像、文档等非结构化输入处理服务的隔离；
  • 容器镜像中的系统依赖如何持续获得安全回补。

可以转化的内容或产品实验

  • 画出“文件上传 → 解析服务 → SSO → Agent → GitHub”的信任链；
  • 制作一个连接器权限扩散的交互模拟；
  • 整理 AI Agent 产品的 SSO 与第三方连接器检查清单；
  • 对比“模型安全限制”与“系统实际授权能力”的差别。
